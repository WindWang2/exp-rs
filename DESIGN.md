## Problem Statement
Undergraduate remote sensing course students need an intuitive, lightweight, and high-performance experimental software. Existing GIS platforms (like QGIS or ENVI) are bloated, have an overwhelming number of features, and a steep learning curve. At the same time, AI developers require a robust, programmatically controllable remote sensing engine to build automated data analysis agents. 

To achieve maximum development speed and packaging efficiency, we implement a **Hybrid Dependency Integration Strategy**:
- **Linked standard libraries (modular dependencies):** All lightweight, standard open-source geospatial/scientific Python libraries (e.g., `rasterio`, `fiona`, `pyproj`, `opencv-python`, `scikit-learn`, `scikit-image`) are declared directly as dependencies in our package.
- **Source-level ports (code copying / 搬运代码):** For large, monolithic systems with heavy desktop installations (such as QGIS C++ GUI models, Orfeo Toolbox C++ engines), we directly extract, adapt, and compile their specific algorithm or class design codes directly inside our own PyQt/Pybind11 structure. This keeps our application fully standalone and lightweight, without requiring QGIS or OTB to be installed on the student's personal computer.

## What Makes This Cool (The "Whoa" Factor)
The **In-App AI Agent Conversational Dock**. 
Instead of searching through endless toolbars and sub-menus to perform complex band calculations or unsupervised classifications, students and agents can simply chat with the application:
> *"Load the Sentinel-2 image, calculate the Normalized Difference Water Index (NDWI), highlight areas of open water, and show me the statistical area of water bodies."*

The built-in AI agent translates this natural language request into local API function calls, executes them securely, writes the corresponding Python processing code in an embedded editor for educational transparency, and instantly renders the resulting raster layers onto our high-performance canvas.

## Constraints
1. **Hybrid Dependency Lifecycle:** Use modular package dependencies (`rasterio`, `fiona`, `pyproj`, `scikit-learn`) for standard GIS capabilities, but directly copy and compile C++ algorithm blocks for heavy or monolithic systems (like OTB). Zero local desktop QGIS or OTB installations are required.
2. **Dynamic Canvas Rendering:** Paint raster layers smoothly via NumPy overview pyramids, and paint vector shapefiles/GeoJSON as custom `QGraphicsPathItem` nodes on our `QGraphicsView` map canvas, copying QGIS's rendering concepts.
3. **Agent-Controllable Canvas:** The GUI must expose a clean, type-safe Python API that allows local LLMs to manipulate layers, query pixel values, and run processing pipelines programmatically.

---

## Premises
1. **Pragmatic Code Reuse:** Standard modular Python libraries handle 80% of geospatial utility tasks (I/O, basic filters, matrix transforms). The remaining 20% of heavy remote sensing algorithms (MeanShift, SVM/RF, textures) are ported directly from OTB and compiled in C++ locally, ensuring absolute performance with no external bloat.
2. **First-Class C++ Pybind11 (Windows & Linux):** We compile custom, dedicated C++ extensions using Pybind11 and CMake (supporting MSVC on Windows and GCC on Linux) to integrate OTB's C++ source algorithms.
3. **QGIS GUI Architecture Emulation:** We will write our own PySide6 Model-View classes by directly porting the design logic of QGIS's C++ components: **`QgsLayerTreeView`** and **`QgsLayerTreeModel`**, translating their hierarchical slot handling and checkbox state models to Python.
4. **OTB Remote Sensing Core Integration:** For heavy processing (MeanShift segmentation, Random Forest/SVM, PCA), we will **port OTB's C++ algorithms directly into our `src/raster_ops.cpp` module**, compiling them natively inside our package.
5. **The Declarative Processing Toolbox Paradigm:** To preserve the core GIS **"Toolbox" paradigm** (equivalent to QGIS's Processing Toolbox), we will implement a centralized **Tool Registry**.
   - Every remote sensing algorithm is registered with a formal, declarative parameter schema.
   - The **GUI Toolbox Panel** dynamically reads this registry to spawn parameter configuration dialogs for students.
   - The **AI Agent** queries this identical schema registry to generate structured JSON tool calls, ensuring perfect alignment between the UI and the Agent platform.
6. **Lab-Focused UI:** The GUI will focus exclusively on remote sensing labs, featuring:
   - A minimalist Layer Tree (QGIS Model-View architecture).
   - A fast standard Map Canvas using `QGraphicsView` + NumPy-to-QImage.
   - A Spectral Curve Chart widget.
   - The dynamic **Processing Toolbox Panel** (Declarative Registry).
   - The native AI Agent Dock Widget (JSON Tool-Calling architecture).

## Approaches Considered

### Approach A: Rebuild Everything from Scratch
* **Summary:** Matplotlib/QGraphicsView Canvas + pure Python/NumPy processing + custom vector/raster drawing models + custom TIFF reader.
* **Effort:** Huge (~10-12 weeks)
* **Risk:** High
* **Pros:** Complete control over compilation and dependency lifecycle.
* **Cons:** Massive duplication of professional GIS features; lacks mature projection transforms, vector editing, legend rendering, and performance caching.

### Approach B: Standalone QGIS/OTB Hybrid Strategy (SELECTED)
* **Summary:** Pure PySide6 standalone desktop application + Standard geospatial dependencies + custom QGraphicsView canvas + direct Python/C++ ports of QgsLayerTreeModel and OTB MeanShift/SVM algorithms + safe JSON Tool-Calling Agent.
* **Effort:** Medium (~3-4 weeks)
* **Risk:** Low
* **Pros:** High-speed development (leveraging Python scientific packages), zero external desktop application installations required for students, highly professional C++ performance, 100% stable map rendering, absolute execution safety.
* **Cons:** Requires cross-platform C++ compilation pipeline setup for OTB ports.
* **Reuses:** Modular packages (`rasterio`, `fiona`, `pyproj`, `opencv`, `scikit-learn`) as direct dependencies; source-level algorithms from QGIS (rendering layouts, layer model-view structures) and Orfeo Toolbox (MeanShift, Random Forest).

---

## Recommended Approach
We will proceed with **Approach B (Hybrid Dependency Strategy)**. This approach strikes the perfect engineering balance: it leverages standard Python GIS modules to do the heavy lifting of loading and managing coordinates, while directly copying and compiling QGIS's GUI models and OTB's C++ remote sensing algorithms inside our repository, requiring **no QGIS or OTB software installations** on the student's personal computer.

## Success Criteria
1. **Zero Runtime Desktop Dependencies:** Launching `main.py` succeeds instantly on any system with standard Python GIS modules (`rasterio`, `fiona`, `pyproj`, `PySide6`), with no QGIS or OTB desktop application installations.
2. **C++ RS Capabilities:** Native C++ modules compiled via Pybind11 run OTB's MeanShift and Random Forest calculations at raw C++ speed.
3. **Agent Integration:** An AI agent can zoom the canvas, query layer parameters, and call Processing algorithms using structured JSON tool commands seamlessly.
