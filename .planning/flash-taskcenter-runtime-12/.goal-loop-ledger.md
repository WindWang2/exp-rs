### R1 — Implementation (task_center.{h,cpp}, execution_telemetry.{h,cpp})
- D1 aging: `enqueueSteadyStamp` + `effectivePriority` per task;
  `applyAgingSweepLocked()` at the head of every admission pass recomputes
  effective priority via `sicnu::agedPriority` and re-pushes improvers with
  fresh serials (lazy invalidation; comparator is time-free). Env
  `SICNU_TASK_AGING_MS`, default 5000, 0 = off.
- D2 latency classes: `latencyClassForSource` (gui/dialog/toolbox/app/
  agent/mcp/pi → Interactive; prefetch/cache/batch → Batch; else
  Background) → `ResourceRequest.latencyClass` at the weight gate.
- D3 bounded pending: `m_liveTaskCount` counts all non-terminal tasks;
  `enqueueTask`/`submitJobImpl`/`submitPipeline` refuse with `-1` before
  creating any record when `m_liveTaskCount >= m_maxPendingTasks`
  (env `SICNU_TASK_MAX_PENDING`, default 4096, 0 = unbounded). Refusals
  increment `TasksRefused` + `admission/queue_full` trace. Pipeline refusal
  is atomic (preflight `live + dispatchable > cap` before step creation).
- D4 cancel watchdog: `cancelDeadline` armed in `cascadeCancelTargetsLocked`
  BEFORE the Cancelling transition (seam counts armed deadlines); watchdog
  thread (`m_watchdogThread`/`m_watchdogCv`, lazily started) +
  opportunistic `enforceCancelDeadlines()` in `onJobRecord`. Expiry:
  detach `m_taskByJobId` first (late record becomes foreign no-op),
  `setTaskStatusLocked → Canceled`, reason `Engine` if unstamped,
  `CancelWatchdogFired` counter + `cancel/watchdog_timeout` trace.
  Env `SICNU_TASK_CANCEL_TIMEOUT_MS`, default 30000, 0 = off;
  `setCancelWatchdogMs(0)` honestly disarms pending deadlines.
- D5 weight dims: `AdmissionDims` extended (cpuThreads, diskRead/Write/
  networkWeight); descriptor keys `execution.cpuThreads`,
  `execution.diskReadWeight`, `execution.diskWriteWeight`,
  `execution.networkWeight` parsed by `parseAdmissionDims` at submission
  (lock-free) into `m_admissionDimsCache`. Active usage tracked in
  `m_active.usage2` at the `setTaskStatusLocked` seam (enter/leave parity).
  `m_budget2.canLaunch` gate in the admission pass (skipped for transient
  children and when nothing runs — never-starve). Candidate priority fed
  as the already-aged `effectivePriority` with `submitStamp=now` so the
  library's internal re-aging does not double-age.
- D6 estimate warming: resolver snapshot taken under `m_mutex`, invoked
  lock-free; `resolvedEstimateMb`/`estimateResolved` seeded at insert;
  `taskEstimateMbLocked` consults them before the cold path.
  `admissionSnapshot` resolves profile/dims/estimate outside `m_mutex`.
- D7 telemetry funnel: `setTaskStatusLocked` is the single terminal seam —
  TasksCompleted/Failed/Canceled counted exactly once, `m_liveTaskCount`
  decremented there; QueueWait+Dispatched on Dispatching, ExecutionStart on
  first Running, ExecutionEnd + Cancelled (cancel latency) at terminal.
  Duplicate `TasksCompleted` increment in `markTaskCompleted` removed.
- D8 fault points: `taskcenter.dispatch` (skips the engine submit → real
  refused-submit rollback: pre-registration removed, typed failure) and
  `taskcenter.jobrecord` (drops the listener record → lost-record path:
  stranded Cancelling + watchdog + foreign-record no-op). Inert when
  unarmed (~1 relaxed atomic load).
- D9 API compat: all knobs default to master-compatible values; `-1`
  refusal sentinel matches the shutdown path.
