## 3. Gaps (what this track must add)

1. **No fault-transform layer**: nothing applies a scientific fault programmatically to a *copy* of a fixture at runtime. Wrong variants are hand-baked TIFs; no `Fault` object (family, target, magnitude, seed).
2. **No fault/scenario schema**: no declarative document linking fault transform → expected observable deltas → expected diagnosis signature → learning objective → cleanup rules. (Nearest: `wrong_answer_corpus.json` — prose `error_class`, score band only, no seed/transform/diagnosis link.)
3. **No observable-delta model**: kernels assert absolute bounds vs truth; nothing asserts "fault F shifts observable O by ≥ δ relative to a clean run".
4. **No detection-expectation seam for diagnosis**: six signatures are hard-coded; cannot declare "this fault must be diagnosable as signature X" nor score a diagnosis against expectation.
5. **No learning-objective model**: objectives are prose; no LO ids, no LO↔fault↔assertion graph, no coverage report.
6. **No scenario runner**: no copy→inject→measure→compare→diagnose→cleanup→replay loop; no sandbox contract marking faulted copies non-authoritative.
7. **No fault-family registry with metadata** (domain, severity, teaching value, seed policy, sandbox class).

## 5. Risks

- **Build cost**: worktree has no build dir; configure seeded via `--base-cache` from `main/build-dev` (Catch2 FetchContent offline). Keep new tests Qt-free where possible; GDAL adapter isolated in its own lib; heavy integration tests (agent lib) limited to one target.
- **Concurrency**: 4 sibling RS14 worktrees + 10 flash worktrees may build simultaneously → strict `-j1`, narrow targets, no clean builds.
- **Scope creep into open issues**: fault families *touch* the same metadata as issues #1146/#1147 (SAR domain), #1150 (NoData), #1161 (catalog). Rule: faults are *declared scenarios*, not bug repros; no production code fixes; observed issues recorded in `progress.md` only.
- **Silent-fault risk**: a fault that changes nothing observable makes a vacuous test → Slice G self-test requires every registered family to move ≥1 declared observable beyond tolerance, and base fixture digest to be unchanged after run.
