# FINAL_REPORT — Unified Help, Hint & Diagnostic Knowledge System 6.0

Status: in progress (updated continuously; final state at PR time).

## Delivered

### Knowledge layer (`src/help`, target `Sicnu::help`)
- Help ID grammar + kinds + derived diagnostic/parameter id mapping
  (`help_id.h`), case-sensitive verbatim segments, 2+ segments, aliases.
- `HelpDescriptor` core + composed payloads (CommandHelp, ParameterKnowledge,
  AlgorithmPage, GuidanceDescriptor, DiagnosticInfo) — bounded contract v1.
- `HelpRegistry`: duplicate rejection, alias one-hop resolution, reference
  validation, sorted deterministic iteration, upsert for composition.
- `HelpSearchIndex`: deterministic token/CJK-bigram inverted index; score,
  tie-break by id; capped results; release budget <5 ms/query @ 2k topics.
- `HelpContentStore`: data/help JSON loader/validator (id grammar, derived-id
  agreement for diagnostics, alias form, nested parameter expansion).
- `DiagnosticCatalog`: unified lookup over harness/operator/geospatial/
  dataset/preflight/rs; fallback descriptors preserve original codes.
- Providers: `CommandHelpProvider`, `OperatorHelpProvider` (base tier auto-
  derived for every schema parameter; curated tier merged; drift reported).
- `HelpPresenter`/`HelpCompact`/`HelpTopicText`/`HelpMarkdownWriter`.
- Layer guards: no Widgets/Network/app/operator linkage (CMake FATAL_ERROR).

### Adapters (`src/help/adapters`, `src/app/help`)
- `OperatorHelpSource` (RSOperatorRegistry → facts; headless-safe).
- `CommandHelpSource`, `AvailabilityFactsAdapter` (ContextRules predicates →
  fact lists), `HelpSystemController` (composition, F1, binding),
  `HelpEventFilter`, `HelpCenterDialog`, `WorkbenchGuidance`.

### Content (`data/help/**`)
- commands.json (49), workbenches.json (6 + alias), concepts.json (12),
  diagnostics.json (99), operators/*.json (105 operators; flagship deep
  parameter knowledge: sar_speckle, spectral_index, supervised_classification,
  change_detection, temporal_composite, topographic_correction, terrain,
  kmeans, image_fusion…).

### Surface integrations
- Shell: composition + action binding + availability-aware tooltips +
  F1 filter + workbench context + 帮助中心 menu entry.
- Forms: `SchemaFormBuilder::setHelpContext` (parameter knowledge on fields).
- CLI: `--operator-help`, `--help-topic`, `--list-topics`, `--export-help-docs`.
- MCP: `get_tool_help` bounded tool.
- Generated docs: `docs/generated/help/{commands,operators,parameters,
  diagnostics,index}.md` (byte-stable, drift-diffable).

## Known limitations

- Command knowledge requires the source-scan drift test for coverage because
  `CommandRegistry` cannot be instantiated without the GUI shell.
- Help Center uses QTextBrowser (no syntax-highlighted code blocks).
- MCP `get_tool_help` exposes operator help; non-operator tools fall back to
  their catalog descriptions (help ids for commands/GUI-only surfaces are
  not agent-reachable by design).
- docs/generated/help is regenerated by CLI; CI drift-diff is documented but
  local-only (no online CI dependency in this track).
- Generated command pages produced headlessly show ids instead of GUI labels
  for commands whose titles come from the (GUI-only) CommandRegistry; the GUI
  composition renders full titles.
