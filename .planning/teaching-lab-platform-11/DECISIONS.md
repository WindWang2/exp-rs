# DECISIONS — teaching-lab-platform-11

| # | Decision | Alternatives | Rationale |
|---|---|---|---|
| D1 | Grading kernels 2.0 live in NEW `src/agent/lab_grader_kernels.{h,cpp}`; `output_verifier.cpp` gets only minimal additive dispatch | (a) grow output_verifier.cpp inline; (b) separate second grader | (a) grows an already-2400-line file outside our declared write scope (`src/agent/*lab*`); (b) violates "no second grading engine" authority rule. New file keeps business body in-scope; dispatch site stays the single seam (ADR 0150). |
| D2 | Batch 2.0 extends `lab_batch_runner.{h,cpp}` in place rather than new batch engine | new `lab_batch2.*` | D7 file is the declared seam ("do not grow side entry points into cli_lab_commands.cpp"); one engine, additive fields, backward-compatible CSV schema (existing columns preserved, new summary file is separate). |
| D3 | `--report` implemented as a new flag of `lab` command delegating to `src/cli/lab_report_runner.*` | (a) new top-level CLI verb; (b) GUI-only stays | (a) new verb requires main_cli.cpp registration churn in shared file; `lab` verb already owns teaching surface and its parser is the documented extension point. Report authority remains LabReportBuilder — CLI is a shell, no second report implementation. |
| D4 | Recorded grade embedding is built FROM a grade transcript file (digest + body), not by re-grading inside the report builder | re-grade inside builder | Report is a projection of recorded truth (lab_report.h contract); re-grading would make reports non-deterministic and violate the projection rule. Transcript carries its own digest for verifiability. |
| D5 | Pack manifests stored under `data/labs/packs/<lab_id>.pack.json` with sha256/bytes of committed prerequisites | (a) one giant manifest; (b) extend data-specs in place | Per-lab files match the existing per-lab rules/pipelines layout and let a teacher verify one lab. data-specs remain the *requirements* authority (labspec labs); packs are the *verifiable deployment* authority and reference data-specs where present. |
| D6 | labspec labs 8–11 get executable rules files implementing their intent tolerances verbatim; intent files stay (authoring record) | delete intents after porting | Intents are D3/D4 cross-track contracts referenced by pipeline docs; keeping them preserves traceability; drift guard will assert rules match intent claim ids. |
| D7 | New kernels each run their own windowed streaming pass instead of being squeezed into the single value-kernel pass | fold into existing pass | zone-join/spatial-agreement need a second open raster (zones truth) and different accumulation; per-kernel passes keep budget enforcement per assertion and avoid destabilizing the existing pass. Cost: extra read per kernel — bounded by --max-bytes and documented. |
| D8 | Duplicate submission policy: same content (sha256) from two student_ids → both rows carry the grade, flagged `duplicate_of`; identical student_id+content submitted twice → graded once | (a) reject duplicates; (b) ignore silently | Classroom reality: resubmissions happen; graded-once + flagged preserves explainability without surprising failures. No score is invented; the summary exposes the collision for the teacher to judge. |
| D9 | Batch v2 summary JSON body carries no wall-clock timestamps (header-only `generated_utc`), matching grade/report determinism contracts | timestamps in body | Deterministic summaries let H's scale test assert byte-identical outputs for identical submissions. |
| D10 | E-package injection corpus lives in code (`lab_injection_corpus.*`) consumed by evals, not in data JSON | data-file corpus | Keeps refusal logic and its adversarial inputs co-reviewed; data files under data/labs are student-visible and must not contain attack strings. |
| D11 | Out-of-scope discoveries (#1001–#1007, ISSUES.md operator gaps) recorded, not fixed | fix opportunistically | Cross-track ownership (autonomy default 6); fixing other tracks' domains risks conflicts with open PRs #1008/#1009. |
| D12 | Scale test opt-in via Catch2 tag `[scale]` + default bounded 100-submission gate | always 1000 | Resource envelope (ctest -j1, shared dev machine); 1000-run evidence produced once locally and recorded in PERFORMANCE.md. |
| D13 | Fixtures for labs 8–11 grading reuse the D3 closed-form generator tradition (new committed tifs under tests/fixtures/lab/ via a NEW script `scripts/gen_lab_grading_fixtures.py`, numpy+GDAL, fixed seed) | extend gen_lab_fixtures.py in place | gen_lab_fixtures.py writes to gitignored data/labs/_tmp for pipeline verification; grading fixtures are COMMITTED corpus products with a different lifecycle (docs/GRADING.md tradition: generate_fixtures.py). Separate script avoids entangling the two contracts; *lab* naming keeps it in scope. |
| D14 | Windows build/test driver: `cmake --preset build-dev` equivalents already scripted in repo; resource caps per GOAL | ad-hoc ninja | Repro evidence; see PERFORMANCE.md for measured limits. |
| D15 | Fixture generator for the new labspec-lab corpus is a C++ tool (`tests/lab_grading_fixture_gen.cpp`) instead of extending the python generator (D13 amendment) | pip-install osgeo | This host has no GDAL python bindings (recorded as an environment limit); the repo already builds a native sample generator (`tools/generate_sample_data.cpp`), so a C++ tool keeps regeneration possible on every dev/CI host. Committed tifs stay the canonical products; byte-stability comes from closed-form scenes (no RNG/timestamps). |
| D16 | Multi-artifact labs get ONE rules file per graded ARTIFACT; the lab's PRIMARY artifact carries the canonical `<lab>.rules.json` id | one rules file grading many artifacts | `gradeForTeaching` grades ONE artifact per call (ADR 0150 seam); the D16 temporal lab produces series/trend/phenology artifacts. Primary-artifact rules keep `lab --lab <id>` semantics; derived artifacts can declare `<lab>_<artifact>.rules.json` later without schema change. 11.0 ships the four primary rules. |
| D17 | Self-check rules parsing probes the REAL grader (`gradeArtifact(lab, "")` must answer "Artifact does not exist") instead of exposing a second parser | expose parseRules | Second parser violates the single-authority rule; the probe distinguishes parsed-rules (artifact error) from broken-rules (any other usage error) using only the public seam. |
