Section 2: The Rendering Pipeline

Ensuring responsive interactions through async execution

Asynchronous Execution Sequence
  1. User Action: Panning or zooming occurs in MapCanvas.
  2. Snapshot: Canvas creates MapSettings (Extent, CRS, visible Layers, DPU).
  3. Dispatch: A MapRendererJob is spawned in a background thread.
  4. Layer Rendering:
    • Job iterates through visible layers.
    • Each layer requests data from its DataProvider for the current extent.
    • VectorLayer uses its Renderer to draw features onto a per-layer QImage.
  5. Composition: Job flattens all layer images into a single final QImage.
  6. Feedback: Canvas receives the final image and paints it to the viewport.

Handling Large Datasets

  • Tiling: Raster providers will utilize GDAL overviews (pyramids).
  • Simplification: Vector renderers will simplify geometries based on pixel-resolution at the current zoom level.
  • Cancellation: If the user pans while a render is in progress, the current job is aborted and a new one starts.
