### Round 3 — hostprocess teardown abort + crash-respawn ladder (found in review)

The Windows hostprocess suite exposed two PRE-EXISTING defects in the files
this track owns (both reproduced on the master-built binary in the main
checkout, `/projects/exp-rs/build-dev/test_plugin_host_process.exe`):

1. **`unloadPlugin` destroyed the entry mutex while locked** — the map erase
   dropped the last `shared_ptr<PluginHostSessionEntry>` while `entryLock`
   still referenced its `std::mutex`; every Debug-CRT run aborted with
   `mutex destroyed while busy` (Release: silent UB). Fixed by keeping a
   local `shared_ptr` alive across the lock and ending the lock scope before
   the erase.
2. **The crash-respawn proxy never retried after recovery** — the 2-attempt
   loop executed → recovered → fell out of the loop, reporting "restart
   policy exhausted" (E6005) while a freshly respawned worker sat alive
   behind the session. The documented ladder (and the pre-existing test
   comment) is execute → recover once → execute → typed failure. Fixed with
   a 3-attempt ladder; the recovered call now actually runs.

Also: `test_exprs_external_process_win` initially failed only because the
`exprs_ep_helper` fixture target had not been built in this fresh tree; with
the target built all 8 cases pass. The Qt hostile-nesting fixture was reduced
from 1024 to 256 levels because jsoncpp's recursive destructor overflows the
1 MB debug stack at 1024 — still 64x the contract cap.
