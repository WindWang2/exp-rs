# Internationalization (i18n) — zh_CN translation pipeline and the RS glossary

Audience: developers adding or changing user-visible strings, and maintainers of the
terminology layer. This documents the D6 track: how English source text becomes a
Simplified Chinese UI, and how `data/terms/` serves UI, help and the future agent (D9)
from one file.

## TL;DR for developers

- Write user-visible strings as `tr( "English source text" )`. Never hard-code Chinese
  (or any other language) in `src/`.
- Chinese lives in `resources/translations/sicnu_zh_CN.ts` — a **tracked** file. The
  compiled `.qm` is generated into the build tree and is **never committed**.
- After adding/changing strings, refresh the `.ts`:
  ```bash
  ninja -C build-dev sicnu_i18n_update   # lupdate over src/app → sicnu_zh_CN.ts
  # ... fill in the new translations in the .ts (unfinished entries are release-blocked) ...
  ninja -C build-dev sicnu_i18n          # lrelease → build-dev/resources/translations/sicnu_zh_CN.qm
  ```
- `tests/test_i18n` fails on: unfinished/empty `.ts` entries, glossary reference breakage,
  or unwrapped user-visible string literals in the audited modules.

## Runtime behaviour

`main.cpp` installs `sicnu_zh_CN.qm` at startup when the locale asks for Chinese
(`LANG`/`LC_ALL`, overridable with `SICNU_LANG=zh_CN` for demos/tests). Lookup order:

1. `$SICNU_TRANSLATIONS_DIR` (tests/CI override)
2. `<binary dir>/resources/translations/` (build tree layout)
3. `<binary dir>/../resources/translations/`
4. `<binary dir>/translations/`

If no `.qm` can be loaded the app runs with the English source text — it degrades to
English, never to empty strings.

`lrelease` runs as a build-time dependency of the `sicnu_geo_rs` target (`sicnu_i18n`),
so a plain build always produces a current `.qm` next to the binary.

## Conventions

- `%1`, `%2`, … placeholders keep their order in translations (no reordering).
- Keyboard mnemonics: English uses `&File`; the zh translation is `文件(&F)`.
- File-dialog filters keep the `;;` separator; only the display names are translated.
- RS terminology must match `data/terms/rs_glossary.json` (e.g. *radiometric
  calibration* → 辐射定标, *atmospheric correction* → 大气校正). The glossary is the
  single authority; do not invent variants in UI strings.

## The unified RS glossary (`data/terms/rs_glossary.json`)

One JSON array, one entry per concept:

```json
{
  "en": "radiometric calibration",
  "zh": "辐射定标",
  "alias": ["绝对辐射定标"],
  "definition_zh": "将传感器记录的原始量化值（DN）转换为具有物理量纲的辐射亮度或反射率的处理过程。",
  "category": "radiometric",
  "related": ["digital number", "radiance"]
}
```

- Schema: `data/terms/rs_glossary.schema.json` (12 fixed categories, `related[]` must
  reference other entries' `en` values, `en` keys are unique).
- Consumers:
  - **Help system** — `sicnu::help::TerminologyProvider` (`src/help/`) loads the glossary
    (embedded via `data/help/help_content.qrc` as `:/help/terms/rs_glossary.json`) and
    `composeHelpSystem()` derives `concept.term.*` descriptors from it. Terms are
    therefore searchable in the one help catalog — there is no second catalog and no
    content fork.
  - **Translation layer** — the same file pins the terminology used in `sicnu_zh_CN.ts`.
  - **D9 (agent)** — `TerminologyProvider::lookup(en|zh|alias)` is the direct API for
    agent answers; it reads the same file the help system uses.

When authoring glossary entries: `definition_zh` is one classroom-usable sentence —
it is what students and the agent will quote.

## Testing

`ctest -R test_i18n -j1` guards the pipeline:

| Check | What it enforces |
|---|---|
| `.ts` completeness | zero `type="unfinished"` / empty translations, ≥3000 messages, en→zh_CN languages |
| glossary integrity | ≥300 terms, zero loader errors, all 12 categories, `related[]` resolves |
| one catalog | terms appear as `concept.term.*` descriptors and are found by `HelpSearchIndex` |
| sweep audit | no widget-API string literal without `tr()` in the audited modules |

## Known limitations

- `QObject::tr()`-style calls in free functions use the `QObject` context; a few
  pre-existing call sites compare displayed strings against `tr()` results. This is
  safe only because the translation layer maps identical English sources to identical
  Chinese everywhere. Do not introduce per-context variants of such shared strings.
- `src/` outside `src/app` (agent, processing, …) may still carry Chinese literals;
  those surfaces are out of the D6 scope and are translated in later tracks.
