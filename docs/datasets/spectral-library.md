# Built-in Spectral Library & Material Priors (D12)

The platform ships a redistributable, license-clean spectral library at
`data/spectral/library.json` (format v2, 25 entries, ~215 KB uncompressed,
well under the 5 MB budget). It feeds the spectral workbench
([ADR 0092](../adr/0092-*.md)), wavelength-aware matching
([ADR 0096](../adr/0096-*.md)), resampling ([ADR 0079](../adr/0079-*.md)) and
— through the material-prior API ([ADR 0146](../adr/0146-spectral-library-material-priors.md))
— the knowledge (D8) and teaching-copilot (D9) layers, plus lab experiments
(D3c) that only need to reference `library_id`.

## Files

| File | Purpose |
| --- | --- |
| `library.json` | The library itself (committed, offline-distributable). |
| `library.schema.json` | JSON Schema of record for curated libraries (draft-07). |
| `sensors.json` | Nominal band grids for Landsat-8/9 OLI, Sentinel-2 MSI, GF-1/2 PMS. |
| `LICENSES.md` | License (CC0-1.0) + per-entry provenance; test-asserted zero drift. |
| `tools/generate_library.py` | Deterministic generator + physics self-checks. |

## Material taxonomy (fixed, 12 classes)

`bare_rock`, `burned_area`, `cloud`, `cropland`, `ice`, `impervious_surface`,
`sand`, `shadow`, `snow`, `soil`, `vegetation`, `water`.

Coverage floor: every class ≥ 1 entry; the key classes `water`, `vegetation`,
`soil`, `impervious_surface` carry ≥ 3 entries with genuine within-class
variability (e.g. clear vs mesotrophic vs turbid vs eutrophic water).

## Data contract

Every entry carries: stable slug `id`, `material` (from the taxonomy),
`subclass`, per-entry `wavelengths` / `fwhm` / `reflectance` arrays on a
shared 5 nm grid over 400–2500 nm, and full provenance (`source`, `license`,
`citation`, `synthetic: true`, `derivation`).

Hard constraints (enforced by `SpectralLibrary::validateLibrary` /
`Library::loadValidated`; violations fail the load naming the entry — entries
are never silently dropped):

- wavelengths strictly increasing and finite, sized to the spectrum;
- reflectance finite and within [0, 1];
- FWHM finite and > 0, sized to the spectrum;
- unique slug ids; non-empty name;
- non-empty `source` / `license` / `citation`;
- `synthetic: true` requires a non-empty `derivation`.

`SpectralLibrary::Library::load` keeps accepting the v1 workbench format
(shared root grids, `name`+`spectrum` entries, no provenance), so existing
user files and the workbench dialog keep working; v1 files simply fail the
strict loader.

## All spectra are synthetic — and why

License-first policy: no third-party measured spectrum ships until its
redistribution terms are unambiguous. Every entry is a physics/textbook-
grounded parametric model generated by `tools/generate_library.py`; the
`derivation` field records the parameters and the `citation` field cites the
physical literature grounding the magnitudes (Kou et al. 1993 for water
absorption, Jacquemoud & Baret 1990 for canopy reflectance, Warren & Brandt
2008 for ice optics, ...). See [LICENSES.md](../../data/spectral/LICENSES.md).

The generator's self-check gates keep the C++ smoke tests green by
construction: with a clear-water query the two best non-self matches are water
entries; with a healthy-vegetation query the two best are vegetation-family
entries (crops are physically vegetation-shaped; the family gate accepts
`vegetation` + `cropland`).

## C++ API (src/processing/algorithms/spectral_library.{h,cpp})

```cpp
SpectralLibrary::Library lib;
QString err;
SpectralLibrary::Library::loadValidated(
    "data/spectral/library.json", &lib, &err);

// indexing (O(entries) scans; no material knowledge in C++)
const QStringList materials = lib.materials();
const QVector<SpectralLibrary::Entry> waters = lib.byMaterial("water");
const QVector<SpectralLibrary::Entry> visOnly =
    lib.byWavelengthRange(450.0f, 520.0f);

// material priors for the knowledge / teaching layers (stable JSON)
const QJsonObject vegPriors = lib.priorsFor("vegetation");
// {"material":"vegetation","entryCount":3,"subclasses":[...],"entries":[...],
//  "syntheticOnly":true,"wavelengthRangeNm":{"min":400,"max":2500},
//  "bands":{"blue":{"windowNm":[450,520],"min":...,"mean":...,"max":...},
//           ...,"nir":{...},"redEdge":{...},"swir1":{...},"swir2":{...}}}

// sensor alignment (ADR 0079 Gaussian SRF resampling)
SpectralLibrary::SensorProfile s2;
SpectralLibrary::SensorProfile::loadSensor(
    "data/spectral/sensors.json", "sentinel-2-msi", &s2, &err);
SpectralLibrary::Library onS2;
lib.resampleTo(s2, &onS2, &err);   // entries tagged "resampled", "sensor:sentinel-2-msi"
```

Band windows used by `priorsFor` (sensor-agnostic, generic): blue 450–520,
green 520–600, red 630–690, redEdge 700–740, nir 760–900, swir1 1550–1750,
swir2 2080–2350 nm. Statistics are computed from the data at query time.

## Consumption seams

- **D3c lab experiments** reference the library by
  `library_id = "rs-studio.builtin-spectral-library.v1"` (root `id` field).
- **D8 capability knowledge** reads `priorsFor(material)` JSON directly
  (e.g. to state "water is dark in NIR: max 0.02" from shipped data).
- **D9 teaching copilot** combines `byMaterial` + `priorsFor` + the
  `derivation` strings for explainable material facts.
- **Spectral workbench (D6 UI)** keeps loading the same file through
  `Library::load`; the strict loader is available to curated paths.

## Known class ambiguities (documented, not bugs)

SAM is shape-based, so the classic ambiguities are expected and preserved
honestly: clear water ↔ shadow ↔ burn (all dark), crops ↔ natural vegetation
(green canopies), dry grass ↔ dry soil. The generator prints a cohesion
report for review; the smoke gates above define the contract that must hold.

## Regenerating

```bash
python3 data/spectral/tools/generate_library.py            # write library.json
python3 data/spectral/tools/generate_library.py --check-only  # physics gates only
```
