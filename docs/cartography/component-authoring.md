# Component Authoring Guide (Cartography Design System 4.0)

Components are declarative descriptors of recurring cartographic furniture
(north arrows, legends, color bars, titles, charts, …). They live in
`data/cartography/components/*.json`, load through `ComponentRegistry`, and
parameterize how `MapSpecCompiler` creates QGIS layout items — they never
render anything themselves. QGIS-native objects stay the single truth
(ADR 0127/0130).

## Descriptor schema v2

```jsonc
{
  "id": "legend/categorical",            // required, "family/name"
  "version": 1,                          // integer, default 1
  "category": "legend",                  // required, see table below
  "semantic_roles": ["legend.primary"],  // roles stamped onto items
  "description": "Class-based legend …",
  "parameters": { "title": "图例", "columns": 1 },   // knobs; also item-shaped
  "defaults":   { },                     // item-shaped fields merged into items
  "variants": [                          // style families, no near-duplicate files
    { "id": "multi-column", "parameters": { "columns": 2 } }
  ],
  "layout_constraints": {                // descriptive metadata (tools/UI);
                                         // not solver input — item anchors are
    "anchor": "free|edge|corner|map-frame",
    "preferred_positions": ["right-rail"],
    "margin_mm": 6,
    "min_size_mm": [30, 20],
    "max_count_per_page": 2
  },
  "compatibility": {                     // descriptive metadata for discovery
    "requires_map_frame": true,
    "map_types": ["raster", "vector"],
    "result_types": ["classification"],
    "crs_requirements": "projected_preferred"
  },
  "data_bindings": [                     // what an agent must bind to use it
    { "name": "renderer", "source": "map_ref.renderer", "required": false }
  ],
  "validation": { "min_font_pt": 12 }    // hints surfaced to tools
}
```

Categories → MapSpec collections (`collectionForCategory`):
`north-arrow→north_arrows`, `scale-bar→scale_bars`, `legend→legends`,
`color-bar→colorbars`, `title`/`subtitle→titles`, `text→labels`,
`grid→grids`, `chart→charts`, `map-frame→map_frames`,
`inset-map→inset_maps`, `annotation→annotations`,
`source-note→source_notes`, `frame→constraints`, `publication→labels`.

## Variants vs. new descriptors

Use a variant when the family, semantics and geometry stay the same and
only parameters/defaults change (`scale-bar/single#line-ticks-down`,
`title/main#compact`). Write a new descriptor when semantics or layout
behavior differ (`legend/categorical` vs `legend/change-transition`).
The catalog-drift test fails on duplicate variant ids and validates every
declared variant resolves.

## How the compiler consumes components

Every MapSpec item may carry `source_component` — a string id or
`{"id": "...", "variant": "..."}`. `applyComponentDefaults` deep-merges the
component's defaults and variant parameters *under* the item's explicit
fields. Precedence (ADR 0130; slot `content` is merged into the item before
component resolution, so it outranks generic component styling):

```
item fields (incl. slot content) > variant parameters > component defaults
> token set > compiler built-in
```

Unknown references never fail a compile; preflight reports them
(`MAP_UNKNOWN_COMPONENT`) and repair strips the dangling reference (no
content is lost — nothing resolved anyway).

Field names in `defaults` must be item-shaped fields the compiler
understands (`interval`, `style`, `units_per_segment`, `svg`,
`north_mode`, `columns`, `chart`, `ramp`, `font`, …). Descriptor parameters
that only tools read (`size_mm`, `interval_deg` knobs) live in
`parameters`.

## Registration and validation

- Disk: drop the file into `data/cartography/components/` (loaded lazily;
  `SICNU_CARTOGRAPHY_DIR` overrides the base directory).
- Programmatic: `ComponentRegistry::instance().registerComponent(json)`.
- `validateComponentDescriptor` checks: string id, known category, object
  shapes for `parameters`/`defaults`/`validation`/`compatibility`,
  `variants` array with unique string ids, `data_bindings` entries with
  string `name`, integer `version`.

## Catalog contract (drift-enforced)

1. Every descriptor validates against schema v2.
2. Every declared variant resolves via `resolveComponent`.
3. Every component drives a compilable item — the catalog-drift test
   instantiates each component into a minimal MapSpec (supplying only live
   data a component cannot know: sample chart data, geometry) and compiles.
   The exception is `frame`-category descriptors (`frame/classic`): their
   items are style metadata for the `constraints` collection and are not
   compiled into layout items.
4. `data/cartography/index.json` is generated by `buildCatalogIndex()`;
   the drift test regenerates and compares byte-exact (regenerate with
   `SICNU_CARTOGRAPHY_REGENERATE_INDEX=1` in the test environment).

## Agent surface

- `cartography:list_components` (paged, category filter)
- `cartography:get_component` (full descriptor)
- `cartography:catalog_index` (machine index incl. components)
